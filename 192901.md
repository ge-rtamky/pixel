# LinkVault Resource Aggregator

LinkVault is a production-grade technical resource aggregation and external link management system designed for developers, technical writers, and research engineers who need to systematically catalog, validate, and distribute large volumes of external reference materials. The project addresses the common pain point of managing hundreds of distributed technical articles, documentation references, and news items across multiple domains by providing a unified indexing layer with health monitoring, metadata extraction, and structured query interfaces. Target users include DevOps engineers maintaining internal documentation portals, technical content curators building learning paths, and data engineers who require reproducible link pipelines for knowledge graph construction.

The system operates as a stateless link processing engine that consumes raw URL lists, performs availability checks, extracts contextual metadata via HTTP headers and HTML content sampling, and exposes the enriched dataset through a RESTful API and a lightweight static frontend. LinkVault is not a search engine nor a link shortener; it is a curation layer that helps teams maintain high-quality external reference collections with minimal operational overhead. The current release (v2.1.0) supports batch import of up to 10,000 URLs per job, incremental update strategies, and pluggable validation rules for domain whitelisting and content-type filtering.

## 功能概览

- **Bulk URL ingestion with deduplication** – Accepts plain-text URL lists or CSV feeds with optional tags, automatically normalizes entries and eliminates duplicates using a Bloom filter backed by Redis.

- **Automated availability probing** – Performs asynchronous HEAD and GET requests with configurable timeouts and retry policies, recording HTTP status codes, response times, and TLS certificate validity.

- **Metadata enrichment pipeline** – Extracts title, description, and content-language from HTML meta tags; falls back to Open Graph and Dublin Core when available.

- **Structured query API with pagination** – Exposes filtering by domain, status code, last-check timestamp, and custom tags through a JSON:API-compliant endpoint with cursor-based pagination.

- **Static snapshot generation** – Produces daily static HTML snapshots of the curated link list for archival and offline access, with optional GPG signing.

- **Health dashboard and alerting** – Provides a built-in Prometheus metrics endpoint for monitoring check success rates, average latency, and domain distribution; integrates with Alertmanager for stale link notifications.

- **Pluggable validation rules** – Supports custom JavaScript or Python validation hooks for domain allowlisting, MIME-type verification, and content-size limits.

## 应用场景

- **Technical documentation portal maintenance** – Documentation teams managing external reference sections in product manuals can use LinkVault to periodically verify that all cited tutorials, API references, and specification documents remain accessible, automatically flagging broken links before each release cycle.

- **Research literature curation** – Researchers compiling supplementary material for papers or systematic reviews can import large collections of reference URLs, enrich them with metadata, and export structured BibTeX or JSON feeds for integration with reference managers like Zotero or Mendeley.

- **Internal developer knowledge base** – Platform engineering teams can aggregate links to internal runbooks, monitoring dashboards, and CI/CD pipelines across multiple repositories, providing a single searchable interface that reduces onboarding friction for new engineers.

- **Compliance and audit trail** – Legal and compliance officers can maintain a permanent record of external references used in regulatory submissions, with timestamped availability snapshots and change logs that demonstrate due diligence over time.

## 快速开始

The following commands clone the repository, install production dependencies, and launch the service with default configuration:

```bash
git clone https://github.com/linkvault/linkvault.git
cd linkvault
make install
cp .env.example .env
make run
```

For development setup with hot-reload and test fixtures, use:

```bash
make dev
```

The service will bind to `0.0.0.0:8080` by default. Visit `http://localhost:8080/health` to verify that the system is operational.

## 安装要求

| 依赖组件 | 必需版本 | 说明 |
|----------|----------|------|
| Go | 1.21.x or higher | Core runtime; uses generics and new `slog` package for structured logging |
| Redis | 7.0.x or higher | Used for deduplication cache, session storage, and distributed rate-limiting |
| PostgreSQL | 14.x or higher | Primary datastore for link metadata, check history, and tag associations |
| Node.js | 20.x LTS | Required only for frontend asset build and static snapshot generator |
| Make | 4.x or higher | Build automation and task orchestration (BSD make also supported) |
| Git | 2.30.x or higher | Required for clone and version tagging operations |
| Docker | 24.x or higher | Optional but recommended for running integration tests and local Redis/PostgreSQL containers |

## 常见问题

**Q: How does LinkVault handle link rot or temporary unavailability?**

A: The system distinguishes between transient failures (timeouts, 5xx errors) and permanent failures (404, 410) through a configurable retry policy. By default, each URL is checked three times over a 24-hour window with exponential backoff. If a URL fails all attempts, it is marked as `stale` in the database and excluded from daily snapshots. Operators can configure alert thresholds to receive notifications when the stale ratio exceeds a certain percentage (default 5%). Additionally, the system maintains a history table that records every check attempt, allowing downstream consumers to implement custom decay or deprioritization strategies.

**Q: Can I extend the metadata extraction logic to support custom fields like author or publication date?**

A: Yes. The enrichment pipeline is designed with a plugin architecture using Go interfaces. Developers can implement the `Enricher` interface defined in `pkg/metadata/enricher.go` and register their custom extractor in the `internal/enrichment/parser.go` factory. The system currently includes built-in extractors for Dublin Core, Open Graph, and Schema.org properties, but custom extractors are loaded at startup via a configuration map. For example, to extract `dc:creator` as `author`, you can add a mapping in `config.yaml` under `enrichment.custom_fields`. No core code modification is required for simple field mappings.
